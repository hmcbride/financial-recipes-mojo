The book prints 77 output boxes ("Output from C++ program" and "Output from
Matlab program"). `audit/book_examples.mojo` reruns the program of every box
with the `finrecipes` package and this table compares each printed number
with the port's result. Inputs that Matlab merely echoes back are left out.

The Monte Carlo examples (boxes 47 to 51, 57 and 77) are run with the package's
emulation of the GNU C library `rand()`, seeded with 1 at the start of each box,
which is the random sequence the book's programs used. They are therefore
compared digit for digit, like every other number.

## How to read the result column

- **match**: the port agrees with the book to within half a unit of the last printed digit.
- **last digit**: the port differs by at most one unit in the last printed digit.
- **DIFFERS**: the port gives a different number.
- **not comparable**: nothing in the port to compare with (reason given).

## Notes on individual boxes

- **Box 73.** The book's C++ Code 25.4 fills T+1 of the T+2 option values at the last tree level and then reads one element past them, so the printed prices depend on a stray memory value. The port fills the missing payoff. `tests/test_ho_lee.mojo` shows that the printed 6.4857 and 6.35411 are exactly what results when the stray value is 0.5.
- **Box 53.** The port reproduces the printed 5.74339, but the listing passes the cost of carry `b` where the payout rate is expected, and its Newton iteration does not converge for this example. The published Barone-Adesi Whaley value is 3.52, which `option_price_american_call_approximated_baw_corrected` returns.
- **Box 35.** The book labels the output a call, but the program calls `futures_option_price_put_european_black`. The printed 0.851476 is the put price, and the port's put matches it.
- **Box 75.** Demonstrates the Boost C++ date library and prints the clock time of the run. Nothing to port or compare.
- **Box 12.** The Matlab convexity formula uses t squared and gives 6.6272; C++ Code 4.6 (box 13) uses t(t+1) and gives 8.93248. Both are reproduced; the Matlab value is computed inline in the audit program, because the package ports the C++ routine.
- **Box 5.** The book has no routine for these two conversions; they are evaluated inline in the audit program.
- **Box 18.** The discount factors come from `mat_solve`; the conversion to annual rates is evaluated inline.
